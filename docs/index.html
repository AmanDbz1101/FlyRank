Agentic Content Decline Investigator

A Multi-Agent System for Investigating Why Content Pages Decline in Search Visibility

FlyRank ML Internship 2026 · Capstone Project
Built on the FlyRank internship dataset

Abstract. Content teams invest effort creating pages that drive organic traffic, but visibility can erode without clear warning. This project asks: can we identify which content pages are declining in search visibility, and generate actionable investigation reports? We built a multi-agent system — a rule-based Planner, a DuckDB Investigator, and a Groq LLM Synthesizer — chained via LangChain's Runnable interface. On a population of 125,573 pages from the FlyRank internship warehouse, a Logistic Regression model achieves P@50 = 0.880 (1.70× base rate), outperforming a hand-crafted baseline rule at P@100 = 0.750. The agent pipeline generates decline investigation reports that cite specific warehouse evidence and recommend actions (REFRESH / MONITOR / NO_ACTION). All work is observational; causal claims require a controlled experiment.

1. Introduction

Organic search is a primary traffic driver for content-heavy sites. When a page's impressions drop, editors face a triage problem: which pages are actually declining, and which ones are worth investigating? Manual review of thousands of pages is infeasible. A scoring system that ranks pages by decline risk — and explains why — lets editors focus their limited time on the pages most likely to recover with intervention.

This project builds a content decline investigator with two components:

  1. A ranking model that scores 125K+ pages by decline risk, using only signals knowable at a single decision moment (March 31, 2026).
  2. A multi-agent pipeline that, given a page, generates a human-readable investigation report citing warehouse evidence and recommending an action.

The work is positioned as decision-support, not prediction. The model tells editors where to look; the agents tell them what the data shows. Neither claims to know why Google ranks pages the way it does.

Research Question

Given March 2026 search and analytics signals, can we rank content pages by their likelihood of declining in April — and generate actionable investigation reports for the highest-risk pages?

3. Methodology

Feature Vector

8 inputs, all knowable at the decision moment (2026-03-31):

FeatureDescriptionNaN handling
log_mar_impressionslog1p(March GSC impressions)None
ctr_marMarch clicks / impressions × 1000 (no clicks)
mar_avg_positionImpression-weighted March position indexfillna(0)
momentum_feb_to_mar_pct(Mar − Feb) / Feb × 100fillna(0) — 16% missing
engagement_rate_marGA4 engaged / sessions × 100fillna(0) — 51% missing
has_clicks1 when March clicks > 0Never missing
has_feb_data1 when page has February rowsNever missing
has_ga41 when March GA4 sessions > 0Never missing
Missingness is a signal, not noise. The has_* flags make the measurement gap explicit. GA4 availability is three-valued (TRUE / FALSE / NULL); we filter with IS TRUE, not fillna(0).

Baseline Rule

A hand-crafted scoring rule from Week 4:

score = risk_points + ctr_shortfall + impact
risk_points = 1 + 2×(CTR gap OR no clicks at top-10) + 1×(spike)
ctr_shortfall = clip(1 - ctr_ratio, 0, 1)
impact = log1p(clicks_lost) / 10

Models

ModelWhyComplexity
Logistic RegressionReadable coefficients; honest floor for "can the signals do anything?"Low
Random ForestHandles nonlinear interactions; compared to LR so complexity earns its placeMedium

Validation Design

Client-grouped 4-fold cross-validation (GroupKFold by client_hash_id). A fold never contains pages from clients the model trained on. This prevents information leakage from shared site structure.

Why grouped? Pages from the same client share patterns (same site structure, same editorial process). A random split lets the model memorize a client and meet it again in testing. Week 3 measured this: random split 0.622 vs. client-grouped 0.597 ROC AUC — a 0.025 inflation from leakage.

The pooled out-of-fold test set contains all 125,573 pages, so baseline numbers are directly comparable.

Leakage Controls

  1. All features strictly before the label window (March → April).
  2. No label-derived features (trend_direction, trend_pct excluded).
  3. No product flags (health_score not in dataset).
  4. Client-grouped validation: no client in both train and test.
  5. Baseline rule reproduced on the full population before comparison.

Agent Pipeline

┌─────────────────────────────────────────────────────────────┐ │ DeclineInvestigatorPipeline │ │ (LangChain RunnableSequence) │ ├─────────────────────────────────────────────────────────────┤ │ │ │ ┌──────────────┐ ┌──────────────────┐ ┌───────────┐ │ │ │ Planner │───▶│ Investigator │───▶│Synthesizer│ │ │ │ (rule-based) │ │ (DuckDB) │ │ (Groq LLM)│ │ │ └──────────────┘ └──────────────────┘ └───────────┘ │ │ 7 rules query + classify Qwen 3.8-27b │ │ → hypotheses → SUPPORTS/ → report + │ │ CONTRADICTS/ action │ │ INCONCLUSIVE │ └─────────────────────────────────────────────────────────────┘

Planner — Rule-based (no LLM). 7 rules generate hypotheses from page features. Deterministic: same inputs produce the same hypotheses.

Investigator — Executes DuckDB queries against the warehouse to test each hypothesis. Classifies evidence as SUPPORTS, CONTRADICTS, or INCONCLUSIVE.

Synthesizer — Groq-hosted Qwen 3.8-27b generates a 3–5 sentence report citing specific evidence. Recommends REFRESH, MONITOR, or NO_ACTION. Falls back to template-based reports if the API is unavailable.

Key finding: LR beats the baseline at P@50 (0.880 vs. 0.700, 1.26× improvement). For a 50-page review budget, the model catches 44 actual declines vs. 35 for the rule. At P@500, RF's deeper queue wins (0.754 vs. 0.714).

Interpretation

LR coefficients (standardized): has_feb_data (+0.347) is the strongest positive predictor — pages without February data are more likely to decline. ctr_mar (−0.169) and mar_avg_position (−0.126) are negative — higher CTR and better positions reduce decline risk.

RF feature importance: mar_avg_position (21.8%), ctr_mar (21.5%), and has_feb_data (15.7%) dominate. Position and CTR together explain 43% of the model's decisions.

Error Analysis

The baseline rule misses Feedly articles (32% of declines) — the model partially recovers this blind spot. False positive rate is ~30% across momentum bands, concentrated in pages with high momentum (spikes that may revert).

5. Limitations & Honest Framing

This work is observational, not experimental. It cannot claim:
  • "Refreshing a page will cause traffic to recover" — no controlled experiment was run.
  • "The model predicts Google's algorithm changes" — we model outcomes in one portfolio, not Google's ranking.
  • "Page X declined because of Y" — cross-sectional data does not support causal claims.

What the model does

Rank pages by decline risk. The model says "Page A shows stronger decline signals than Page B" — this is supported by the data.

What the model does not do

Predict whether a specific page will decline. The model cannot say "Page A will decline by 15% next month."

Data limitations

  • Unbalanced panel — Only 44 of 104 clients have March data; absent pages are invisible.
  • GA4 sparsity — 51% of rows have no GA4 data. The has_ga4 flag makes this explicit.
  • Single label window — April < 80% of March. Cannot distinguish seasonality from real decay.
  • Low ROC AUC — LR: 0.520, RF: 0.555. Modest overall separation, but precision@K is strong at the top.

Agent limitations

  • Rule-based Planner has limited hypothesis diversity.
  • Single-window queries cannot detect multi-month trends.
  • LLM may generate plausible but unsupported claims — evidence list constrains the output.
  • Reports reflect March 2026 state only; warehouse is a snapshot, not live.

Priority for a 50-Page Review Budget

Using LR P@50 = 0.880: 44 of the top 50 pages flagged by the model are actually declining. The baseline rule catches 35 of 50 at the same budget. The model saves editorial time by concentrating true declines at the top of the queue.
